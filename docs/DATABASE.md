# PROBAHO (প্রবাহ) — Database Architecture & Schema

## Overview
PROBAHO uses PostgreSQL with relational integrity across supply nodes, medicines, batches, shipments, and audit events. A seeded in-memory adapter allows seamless execution without an external database instance during rapid demonstration.

## Entity Relationship Summary

```
[suppliers] ──< [ingredient_shipments]
     │
[ingredient_materials]
     │
[medicines] ──< [inventory_batches] >── [facilities]
     │                                        │
[consumption_records] ────────────────────────┘
     │
[forecasts]
     │
[recommendations] ──< [approvals]
     │
[audit_logs] (Hash-chained SHA-256)
```

## Schema Details
- `users`: Authenticated user accounts with role-based permissions (`admin`, `approver`, `facility`, `analyst`).
- `facilities`: Upazila health complexes (UHC) and community clinics (CC) with GPS coordinates and storage capacities.
- `medicines`: Essential tracer medicines (Paracetamol, Amoxicillin, Metformin, Omeprazole, ORS) linked to their required Active Pharmaceutical Ingredient per unit.
- `ingredient_materials`: Raw chemical specifications and source countries.
- `suppliers`: Upstream Active Pharmaceutical Ingredient vendors with reliability and delay metrics.
- `ingredient_shipments`: Tracking status (`scheduled`, `in_transit`, `delayed`, `delivered`) and port of entry.
- `inventory_batches`: Batch numbers, manufacture dates, expiry dates, and usable unit quantities.
- `consumption_records`: Daily synthetic consumption records across 12 months.
- `recommendations`: Inter-facility transfer proposals generated by the OR-Tools optimizer.
- `approvals`: Human authorization records with user identity, decision, and clinical reason.
- `audit_logs`: Append-only, tamper-evident log linking each entry via `event_hash = SHA256(previous_hash + canonical_json(event))`.
